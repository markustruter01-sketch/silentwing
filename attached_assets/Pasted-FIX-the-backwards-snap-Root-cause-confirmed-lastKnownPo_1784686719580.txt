FIX the backwards-snap. Root cause confirmed: lastKnownPos is stored as the
raw transponder position (seen_pos seconds old) but timestamped as now, so
extrapolation restarts from a past position. Fix both faults:

FIX 1 — Age-compensate the incoming position (the core fix):
On each accepted poll, before storing lastKnownPos, project the raw position
FORWARD by its own staleness so it represents NOW, not seen_pos seconds ago:

  ageS       = ac.seenPos ?? 0
  hRad       = ac.heading * PI/180
  gsMps      = ac.groundSpeed * KT_TO_MPS
  // advance the stale fix forward to present time
  compX      = rawPos.x + gsMps * sin(hRad) * ageS
  compZ      = rawPos.z - gsMps * cos(hRad) * ageS
  compY      = rawPos.y + vyPerS * ageS
  b.lastKnownPos.set(compX, max(0, compY), compZ)
  b.lastKnownTimeMs = nowMs        // now correct: compensated pos IS the now-position

  Only age-compensate FRESH, moving aircraft (canExtrap). Stale/stationary
  aircraft store raw position as before (they're held + greyed, not moving).

The 1s correction blend must ease toward the age-compensated lastKnownPos
(now representing the present), not the raw stale fix. Since Fix 1 makes
