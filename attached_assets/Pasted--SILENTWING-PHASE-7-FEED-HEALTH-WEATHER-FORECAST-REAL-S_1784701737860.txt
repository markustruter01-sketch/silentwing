## PART 1 — FEED-HEALTH FAILSAFE (safety-critical — build and verify FIRST)

**Why this matters:** a frozen display that still LOOKS live is the single most
dangerous failure state in this product. If the data feed stalls, the controller
must be told loudly and unmistakably — never left staring at stale positions
believing they're current.

**Build:**
- The adapter already tracks feed health (live / lagging / stalled) via time
  since last successful update. Surface it prominently:
  - **live** (fresh data): small green "LIVE" indicator in the top bar (already
    exists) — confirm it reflects real feed state, not a hardcoded value.
  - **lagging** (no update for > LAG_S, default 12 s in live mode / adjust for
    sim tick): the top-bar indicator turns amber and reads "LAGGING — Ns since
    update", counting up.
  - **stalled** (no update for > STALL_S, default 25 s): the ENTIRE viewport
    gets a red border and a prominent banner across the top of the view reading
    "⚠ DATA STALE — DO NOT USE FOR SEPARATION". This must be impossible to miss.
- When stalled, also visually mark ALL aircraft as unreliable (e.g. dim them or
  overlay a subtle stale pattern) so no single track looks trustworthy.
- Recovery: when fresh data resumes, clear the banner/border and return to LIVE.
- Thresholds are named constants.

**Dev test hook:** add a dev-only "simulate feed loss" button (clearly labelled,
dev-gated like the inject-conflict button) that pauses the feed so the failsafe
can be demonstrated on demand.

**STOP after Part 1. Report:**
1. The feed-health state machine code (live/lagging/stalled transitions).
2. Confirm via the dev feed-loss button: does lagging appear at LAG_S, stalled
   + red banner at STALL_S, and does it recover on data resume? Raw state trace.
3. Confirm the green LIVE indicator reflects REAL feed state, not a constant.

## PART 2 — REAL SECTOR LOAD (replace the fake placeholder)

**Current state:** sector load is `Math.min(99, count * 11)` — a meaningless
placeholder that shows red 99% constantly. Replace it with a real metric.

**Build:**
- Define sector load as a meaningful measure of controller workload in the
  terminal area, e.g.: count of aircraft WITHIN the terminal area (the same
  ~15nm/FL150 filter used by the alert detectors) as a percentage of a
  configurable comfortable-capacity constant (SECTOR_CAPACITY, default e.g. 20
  aircraft = 100%). Cap display at 100%.
- Only count terminal-area traffic, NOT the full 50nm feed (parked GA at other
  fields shouldn't inflate Brisbane's load).
- Colour: green < 60%, amber 60-85%, red > 85%.
- State the capacity constant and formula used.

**STOP after Part 2. Report:**
